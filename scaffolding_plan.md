# Scaffolding Plan

> **Instructions for the implementing LLM:** Create only the project structure
> described in this document. Do not implement model training, EDA, data
> fetching, notebook content, API behavior, or tests. Use the exact
> `pyproject.toml` contents below. Run only the setup and verification commands
> in section 8.

## 1. Goal

Create a Git-versioned `uv` workspace monorepo for the DPP DSML take-home test.
The repository must contain:

- one package for the classical ML project (Zomato delivery-time regression),
- one package for the deep learning / NLP project (Yelp sentiment analysis),
- one FastAPI inference service,
- one shared `uv.lock` and one shared virtual environment at the workspace root.

The repository must be ready for implementation later, but **this task is
scaffolding only**. Do not add real model code.

Leave the existing guideline PDF untouched:

```text
[DPP DSML - Take Home Test] Guideline Exam.pdf
```

## 2. Confirmed decisions

| Decision | Choice |
|---|---|
| Workspace layout | `models/*` for model packages, `apps/*` for services |
| Classical ML path | `models/delivery-time` |
| NLP path | `models/yelp-sentiment` |
| API path | `apps/api` |
| Python version | 3.12 |
| Python pin location | root `.python-version` only |
| Build backend | `uv_build` |
| Source layout | `src/<import_name>/` |
| Data-fetch scripts | Python modules exposed through `[project.scripts]` |
| PyTorch installation | Default PyPI wheels; no custom index override |
| Shared libraries | None yet. Add `libs/*` only when genuinely shared code appears. |
| Database | None |
| Streamlit | Not scaffolded; `apps/*` leaves room for `apps/streamlit` later |

Package names and import names:

| Distribution name | Import name | Path |
|---|---|---|
| `dpp-dsml-takehome` | none (non-packaged workspace root) | root |
| `dpp-delivery-time` | `delivery_time` | `models/delivery-time` |
| `dpp-yelp-sentiment` | `yelp_sentiment` | `models/yelp-sentiment` |
| `dpp-inference-api` | `inference_api` | `apps/api` |

Because the distribution names use a `dpp-` prefix while the import names do
not, the `uv_build` backend must be told the module name explicitly. This is
important; without `[tool.uv.build-backend] module-name = ...`, `uv sync` will
look for `src/dpp_delivery_time`, `src/dpp_yelp_sentiment`, and
`src/dpp_inference_api`, which do not exist.

## 4. Exact file contents

### 4.1 Root `pyproject.toml`

The workspace root is a non-packaged project. It holds workspace configuration,
shared development dependencies, and tool configuration. It has no build
system.

```toml
[project]
name = "dpp-dsml-takehome"
version = "0.1.0"
description = "DPP DSML take-home: classical ML, NLP, and a local FastAPI inference service"
readme = "README.md"
requires-python = ">=3.12,<3.13"
dependencies = []

[dependency-groups]
dev = [
    "pytest>=8",
    "pytest-cov>=6",
    "ruff>=0.9",
    "httpx>=0.28",
]

[tool.uv]
package = false

[tool.uv.workspace]
members = ["models/*", "apps/*"]

[tool.uv.sources]
dpp-delivery-time = { workspace = true }
dpp-yelp-sentiment = { workspace = true }

[tool.ruff]
line-length = 100
target-version = "py312"

[tool.pytest.ini_options]
testpaths = ["models", "apps"]
addopts = "-ra"
```

Notes:

- `package = false` prevents the root from being built or installed.
- The root-level `[tool.uv.sources]` entries apply to every workspace member,
  including `apps/api`.
- Do not add `libs/*` to `members` yet.
